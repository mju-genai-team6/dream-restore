# B2 결과 및 보관 화면

발표 PDF 4~6쪽의 왼쪽 메뉴, 가운데 콘텐츠, 오른쪽 상세 영역을 참고한 화면입니다.

## 구현한 화면

- 스토리보드: 장면 선택, 설명·요소별 확신도, 이미지 생성 진행·실패 안내와 재시도
- 꿈 보관함: 제목 검색, 생성 상태·영상 유무 표시, 선택한 꿈의 결과 재열람
- 영상 결과: 생성 요청, 진행·실패 안내, 완성 영상 재생과 수정 전 영상 구분

예시 모드의 내용 수정은 제목, 장소, 설명 및 기존 요소의 확신도를 직접 고치는 기능입니다. 자연어 명령을 AI가 해석하거나 이미지를 재생성하는 기능은 포함하지 않습니다.

## 실행

`frontend` 폴더에서 `npm.cmd run dev`를 실행하고 `http://localhost:3000`을 엽니다.

## 저장과 서버 연동

예시 모드의 수정본은 `dream-restore:b2-results:v1` 키에 보관합니다. 브라우저 저장이 실패하면 화면에 안내합니다. 최초 기록은 유지하고 장면 수정 시 버전을 추가합니다. 서버 모드의 장면 내용 수정·수정 이력 API는 아직 연결하지 않았습니다.

영상 데이터는 서버의 `is_latest`와 장면별 버전을 함께 확인합니다. 예시 모드에는 완성 영상이 없으며 실제 생성 요청도 보내지 않습니다.

`NEXT_PUBLIC_API_BASE_URL`을 지정하면 서버 모드가 실행됩니다. B1이 전달하는 `/?dreamId={id}&jobId={jobId}`를 사용하며, 새로고침·보관함 재열람 시에도 지정한 꿈만 조회합니다. 꿈과 다른 작업 ID는 오류로 표시합니다.

| API | 용도 |
| --- | --- |
| `GET /dreams` | 보관함 목록·상태·대표 이미지·영상 유무 |
| `GET /dreams/{id}` | 해당 꿈 원문·상태·진행 중 작업·완성 영상 유무 |
| `GET /dreams/{id}/scenes` | 장면 이미지·서버 상태·확신도·요소 ID·active_job |
| `GET /jobs/{id}` | 장면·영상 생성 진행 단계와 실패 사유 |
| `POST /dreams/{id}/jobs` | 실패한 장면 생성 다시 시도 |
| `POST /dreams/{id}/images/retry` | 실패한 이미지 다시 생성 |
| `POST /dreams/{id}/renders` | 영상 생성·재생성 요청 |
| `GET /dreams/{id}/renders/latest` | 검증된 최신 완성 영상과 장면 버전 (404는 미완료) |

실시간 이벤트 API는 사용하지 않습니다. 진행 중 작업 또는 queued·running 장면이 있으면 앞 요청이 끝난 뒤 4초 간격으로 다시 확인합니다. 완료·실패·통신 오류·화면 이탈 시 중단하고, 3분 제한에 도달하면 생성 실패로 바꾸지 않고 수동 새로고침을 안내합니다. 재시도·영상 생성 중 중복 클릭과 화면 이탈 뒤 응답 반영도 막습니다.

장면 이미지는 서버 `status`로 상태를 판단합니다. `image_url`의 `?v=`는 유지하고 `elements[].element_id`를 화면 식별자로 씁니다. 이미지 주소가 있어도 서버 상태가 failed면 실패로 표시합니다.

## 검증

`npm.cmd test`는 서버 응답 변환, 잘못된 꿈·작업 조합, 영상 404·409와 버전, POST 요청, 순차 조회·완료·화면 이탈·3분 제한·통신 오류를 확인합니다. `npm.cmd run lint`, `npm.cmd run build`로 코드 검사와 빌드를 확인합니다.

서버 통합 확인은 기본 가짜 이미지 모드로 먼저 진행합니다. 이는 이미지 생성 비용만 막으므로 STT·LLM 호출은 별도로 확인해야 합니다.

## 제외한 기능

세계관 지도, 패턴 리포트, 인물 등록, 장면 추가, AI 수정 대화는 포함하지 않습니다. 녹음·인터뷰는 B1의 `features/dream-record/`가 담당합니다.
